# Drippy

Snap your outfit and AI rates it: one overall score, the occasions it suits best, a score and reason for every occasion (Work, Interview, Wedding, Party, Date, Brunch, Festive, Gym), plus tips. Results share to Instagram Stories or anywhere else as a 9:16 card.

This is the Phase 1 MVP (score + share). The social feed, community ratings and comments come next. See [the roadmap](#roadmap).

```
web/            Next.js mobile web app (the pilot), deploys to Vercel
ios/            SwiftUI app (iOS 17+), project generated by XcodeGen
supabase/       Postgres schema + `score-fit` edge function (Claude vision)
```

## How it works

1. The app signs in anonymously, so the first scan needs no setup.
2. The photo is resized to 1280px, sent as JPEG to the `score-fit` edge function.
3. The function checks the daily limits (`FREE_DAILY_SCANS` rated photos, default 10; `MAX_DAILY_ATTEMPTS` of any kind, default 30), then asks `claude-haiku-5-5` to rate the outfit against a fixed rubric with a JSON-schema response.
4. The rating is saved in `scans`. The photo itself is kept (privately, in the `scans` bucket) only for scored fits and only while the `SAVE_PHOTOS` flag is on; off-topic, explicit or under-16 photos are never stored.
5. The result row is saved in `scans` and returned. Clients can read only their own scans and can never write a score themselves.

The AI judges clothes, colors, fit and styling only, never the person's body or face (see `supabase/functions/score-fit/prompt.ts`).

## Setup

**Deploying the pilot?** Follow [DEPLOY.md](DEPLOY.md): Supabase (backend) and Vercel (frontend), both on free plans.

### 1. Tools

- **Xcode** from the App Store, then point the command-line tools at it:
  ```bash
  sudo xcode-select -s /Applications/Xcode.app
  ```
- **Homebrew** (https://brew.sh), then:
  ```bash
  brew install xcodegen supabase/tap/supabase
  ```
- **Docker Desktop**, only for running Supabase locally.

### 2. Backend

Create a project at https://supabase.com, and get an API key from https://console.anthropic.com.

```bash
cd FitScore
supabase login
supabase link --project-ref YOUR-PROJECT-REF
supabase db push
supabase secrets set ANTHROPIC_API_KEY=sk-ant-...
supabase functions deploy score-fit
```

In the Supabase dashboard enable **Authentication → Sign In / Providers → Anonymous sign-ins**.

Run locally instead with `supabase start`, then `supabase functions serve score-fit --env-file supabase/functions/.env` (put `ANTHROPIC_API_KEY=...` in that file).

### 3. Web app (pilot)

Needs Node 20+ (`node --version`).

```bash
cd web
npm install
cp .env.example .env.local   # fill in the Supabase URL and anon key, or leave empty for demo mode
npm run dev                  # http://localhost:3000
```

With no Supabase settings the app runs in **demo mode**: every screen works and scans return a sample result, marked "Sample result" on screen.

The camera needs HTTPS, except on `localhost`. On your phone over Wi-Fi (`http://<your-mac-ip>:3000`) uploading a photo works but the camera doesn't, so test the camera on the Vercel deployment.

Deploy: import the repo in Vercel, set **Root Directory** to `web`, add `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY`. Optionally set the function secret `ALLOWED_ORIGINS=https://your-app.vercel.app,http://localhost:3000` so only those sites can call `score-fit`.

### 4. iOS app

```bash
cd ios
cp Config/Secrets.example.xcconfig Config/Secrets.xcconfig   # fill in URL, anon key, Facebook app id, team
xcodegen generate
open FitScore.xcodeproj
```

Run on a Simulator to test the flow with library photos (the Simulator has no camera). Use a real iPhone to test the camera and Instagram Stories sharing.

Instagram Stories sharing needs a Meta app id (https://developers.facebook.com/apps) in `FACEBOOK_APP_ID`.

## Testing the function

```bash
TOKEN=...   # a user access token, e.g. from the app's session or an anonymous sign-in
IMG=$(base64 -i outfit.jpg)
curl -s https://YOUR-PROJECT-REF.supabase.co/functions/v1/score-fit \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d "{\"image_base64\":\"$IMG\",\"occasion_hint\":\"wedding\"}"
```

Check that the same photo scores consistently, that a photo with no outfit returns `"status":"not_scorable"`, and that the 11th rated photo in a day returns 429.

## Roadmap

**Phase 2: social.** Sign in with Apple (upgrade the anonymous account), usernames and profiles, publish a scan as a post, community ratings (1–10, outfit only) shown next to the AI score, comments, follows, Following and Trending feeds, push notifications, deep links from shared stories. App Store guideline 1.2 requires moderation for this: image safety checks before posting, report/block, comment filtering, an admin review queue and an age gate.

**Phase 3: scale and growth.** Image CDN, queue-based scoring with retries, feed caching, weekly challenges and leaderboards, a premium tier (unlimited scans, deeper styling advice) with StoreKit 2, and funnel analytics (scan → share → install).
